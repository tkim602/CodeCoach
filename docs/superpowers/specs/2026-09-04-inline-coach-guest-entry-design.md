# Inline Coach and Guest Entry Design

## Goal

Make CodeCoach guidance feel native inside LeetCode and Programmers editors, keep every inline control usable, provide equivalent Korean and English UI, and replace the promotional guest card with a quiet first-use path.

## Scope

- Replace the large Monaco view-zone card with a lightweight ghost-text presentation.
- Preserve interactive hint, follow-up, dismiss, approach-input, and side-panel actions.
- Apply the same visual language to Monaco, CodeMirror, and Ace without changing editor content.
- Localize all inline UI states in Korean and English from the saved CodeCoach UI language.
- Replace the guest onboarding card with an accessible text-style action below the API-key form.
- Keep the streaming work already included in PR #7 and add regression coverage for it.

Out of scope: new AI request types, pricing or quota changes, backend prompt changes, and changes to the existing API-key storage policy.

## Inline Presentation

The default inline surface is one ghost-text coaching question anchored at the selected or active line. It does not reserve a large block in the editor. Small text actions appear next to or immediately below the ghost text only while a coaching intervention is active.

- Monaco uses an injected-text decoration for the coaching text. A small absolute control row is positioned from the rendered decoration and cursor coordinates.
- CodeMirror uses a bookmark/widget anchored to the target line when the API supports it. If it is unavailable, CodeCoach uses the shared coordinate overlay.
- Ace uses renderer screen coordinates and the shared coordinate overlay.
- The coordinate overlay is clipped to the editor bounds and recomputed on scroll, resize, cursor movement, model change, and content change.
- Rendering never writes the hint into the user's solution text.
- Removing or replacing an intervention clears decorations, observers, subscriptions, timers, and DOM nodes.

The approach input is collapsed by default. Selecting the approach action opens a single-line input in the control row, focuses it, submits with Enter, cancels with Escape, and prevents input events from reaching the host editor.

## Interaction States

The inline renderer supports these semantic states:

1. Prompt: one coaching question and the relevant actions.
2. Input: prompt plus a focused approach field.
3. Loading: localized short status with no duplicate request action.
4. Streaming: progressively updated ghost text without recreating the active intervention.
5. Complete: follow-up actions become available.
6. Error: localized error text and a close action.

Click, pointer, keyboard, paste, composition, and focus events inside CodeCoach controls are isolated from Monaco, CodeMirror, and Ace. A stale request ID or stale intervention token cannot update the current inline surface.

## Localization

Inline interface copy is defined separately for `ko` and `en`. This includes prompts, buttons, input placeholders, loading text, guest-start text, quota text, errors, and full-solution protection messages.

The saved `uiLanguage` controls interface copy. The content script refreshes it when extension storage changes and before rendering a new intervention. The existing `responseLanguage` setting remains responsible for model output language. Changing UI language does not rewrite a response already generated by the model, but all subsequent states and controls use the new UI language.

## Guest Entry

The API-key form remains the primary path. The current purple two-line guest card and its `or` divider are removed. Beneath the save button, CodeCoach shows one accessible text-style button:

- Korean: `먼저 무료로 사용하기 · 10회`
- English: `Try free first · 10 questions`

The action has a visible hover, focus, loading, disabled, active, and exhausted state. Supporting privacy or quota text appears only when it communicates current state or an error. It does not repeat AI marketing copy.

## Streaming

PR #7's BYOK Responses API stream remains incremental. The parser must handle CRLF and LF event separators, multiple `data:` lines, a final buffered event without a trailing blank line, and decoder flush at stream end. Guest responses remain server-buffered and are progressively revealed on the client without altering the final raw text.

## Error Handling

- If an editor-native anchor API fails, render the shared coordinate overlay within the editor instead of showing a detached page-level card.
- If no supported editor can be found, do not render an intervention.
- If the guest trial is unavailable or exhausted, show the localized state and keep the API-key path available.
- If streaming produces no output text, show the existing safe error path.
- Full-solution detection and metadata stripping remain unchanged.

## Tests

- Inline renderer tests with fake Monaco, CodeMirror, and Ace editors verify anchoring, updates, interaction event isolation, and cleanup.
- Localization tests verify distinct Korean and English strings for every inline state and guest entry state.
- Stream parser tests verify chunk boundaries, CRLF, final-buffer parsing, and accumulated raw text.
- Existing root and Cloud Functions tests, typecheck, build, syntax checks, and `git diff --check` must pass.
- Manual smoke checks cover a LeetCode Monaco problem and a Programmers problem at narrow and normal editor widths.

## Success Criteria

- Inline hints visually read as ghost coaching text rather than a card inserted into the editor.
- Typing and all inline actions work without moving focus back to the host editor.
- No Korean or English text is clipped by a fixed view-zone height.
- UI language selection produces matching inline and guest-entry copy.
- Guest entry no longer uses a purple promotional card.
- Existing hint safety and request routing behavior remain intact.
